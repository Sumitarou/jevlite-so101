# ラベル付けの定義（撮影データ）

撮影スクリプト `scripts/capture_samples.py` で付けるラベルの定義と、撮影の経緯をまとめる。
画像そのものは人物・部屋が写り得るため `samples/private/`（git の管理外）にだけ置く。

## 作業台の領域

作業台の白い面の周りに、幅約 5 cm の緑のテープの帯を貼ってある。

| 領域 | 意味 | ゲートでの対応 |
|---|---|---|
| 白い面 | 保護領域 | STOP |
| 緑の帯 | 警告領域 | SLOW |
| それ以外 | — | CONTINUE |

## ラベルの定義

| ラベル | 教師の選択肢 | 定義 |
|---|---|---|
| `center` | C | 白い面に、物の一部でもかかっている |
| `edge` | B | 緑の帯の上だけにある（白には届いていない） |
| `none` | A | 手も物もない |

「物」には手も含む。**影は物として数えない**（影だけが白い面や緑の帯にかかっていても、手も物もなければ none）。

## 原則

1. **ラベルは「置いたつもりの位置」ではなく「画像に写っているもの」で決める。**
   撮影後に画像を見て、定義に合わなければラベルを付け直す。
2. **迷ったら厳しい側（center）にする。** 白にかかっているか判断できない場合は center、
   緑にかかっているか判断できない場合は edge。
3. 緑の帯と白い面が画像に写っていない画角では撮らない（判断の根拠がなくなるため）。

## 撮影の経緯

| セッション | 枚数（none / edge / center） | 扱い | 理由 |
|---|---|---|---|
| `20261010-trial` | 16 / 0 / 2 | **評価に使わない** | コマンドを 3 行まとめて貼り付けたため、ラベルがずれた |
| `20261010-desk-v1` | 9 / 14 / 14 | **評価に使わない**（失敗例として残す） | 画角が近すぎて作業領域の左右の線が写らず、「置いたつもりの位置」と画像の中身が合わなかった（例：edge なのに何も写っていない） |
| `20261011-desk` | 9 / 9 / 19 | **評価に使う** | 緑の帯を貼り、画角を直して撮り直した。焦点は focus_absolute = 30。center 00015〜00019 は後から追加した、白い面の中央付近のはっきりした例 |

- 焦点：設置後に focus_absolute を 0〜80 で比較し、30 に決定した（2026-10-11、`configs/camera.yaml`）。
- **境目の対**：`20261011-desk` の edge 00001〜00009 と center 00001〜00009 は、同じ位置から少し内側に入れて撮った対（edge は緑の帯の上だけ、center は白い面に少しかかる）。この 18 枚は `configs/eval.yaml` の `subsets` で `boundary` の印を付け、評価は「全体」「境目の対」「それ以外」に分けて集計する。
- `20261010-desk-v1` の失敗から、上の原則 1 と 3 を定めた。

## 未解決の課題

- **アームが写る構図での扱い**：今の撮影画像（`20261011-desk`）にはアームが写っていない。
  教師のプロンプトでアームを無視させると、アーム付近の手を見落とす危険がある。
  アームを含む画像を撮影し、アームの扱いを定めたプロンプトを def-v2 として検証する。
- **参照画像の方式とアーム**：教師に「何もない状態」の参照画像と見比べさせる方式（def-v2-ref）は、アームが写る構図ではアームの位置が変わるたびに常に差分が出る。アームを含む画像での検証が必要。
